# Fluxo E4 — Cadastro e registro de serviços

**Feito quando:** O prestador registra um novo serviço, que pode ser vinculado a um atendimento.

**Pré-condição:** Sessão válida obtida em E0. Para vincular um atendimento, o cliente deve estar cadastrado.

## Passos

1. O prestador acessa a página Serviços.
2. Para cadastrar um item no catálogo, informa descrição, duração em minutos e valor.
3. O Frontend envia POST `/catalogo` ao Backend 1.
4. O Backend 1 valida os dados, grava o item na tabela `catalogo` e devolve o registro criado.
5. O Frontend consulta GET `/catalogo` e apresenta o item na lista.
6. O prestador pode utilizar esse item ao criar um orçamento para um cliente (E8).
7. Quando o orçamento é aprovado, o Backend 1 cria automaticamente um serviço vinculado ao cliente, utilizando a descrição, o valor e a duração associados ao orçamento.
8. O Backend 1 mantém os serviços na tabela `servico`. O Frontend consulta GET `/servicos` e apresenta os atendimentos registrados.
9. A API também permite cadastrar um serviço diretamente por POST `/servicos`, informando cliente, descrição e dados do atendimento.

## Diagrama do caminho principal

```mermaid
sequenceDiagram
    actor P as Prestador
    participant F as Frontend
    participant B1 as Backend 1
    participant DB as Banco

    P->>F: Cadastra item do catálogo
    F->>B1: POST /catalogo
    B1->>DB: Insere item no catálogo
    DB-->>B1: Item registrado
    B1-->>F: Resposta 201
    F->>B1: GET /catalogo
    B1-->>F: Lista do catálogo
    F-->>P: Apresenta item cadastrado
    Note over P,DB: Criação do atendimento após aprovação em E8
    P->>F: Aprova orçamento
    F->>B1: PUT /orcamentos/{id}/aprovar
    B1->>DB: Cria serviço vinculado ao cliente
    DB-->>B1: Serviço registrado
    B1-->>F: Serviço aprovado
    F->>B1: GET /servicos
    B1-->>F: Lista de serviços
```
